# Highlight Ask

在 Zotero 阅读器里划选一段文字，直接问 AI。

面向的场景是**读论文和书**：划中一个看不懂的公式或推导，按一下「解释这段」，答案就出现在右侧边栏，公式按 LaTeX 正常排版。

> 状态：个人自用工具，功能完整可用，但**只在我自己的环境（Zotero 10 / Linux）上验证过**。欢迎试用与反馈。

---

## 它解决什么问题

读文献时最常卡住的地方是公式和推导。已有的做法是把选中的文字复制出去、切到网页版 AI、再粘回来——上下文丢失，公式还会在复制过程中变成乱码。

这个插件把这条路径压成一次划选。它不只是「把文字发给模型」，还处理了三件具体的事：

**公式的输入质量。** PDF 的文字层会把分式压平、上下标错位、范数竖线丢掉。同一段内容，文字层抽出来是这样的：

```
L̃GD [ϕ] = L[ϕ] +
  α ∂L
  4 ∂ϕ
  2
  .
```

分式的分子分母被拆成独立行，平方跑到单独一行。所以插件可以把划选区域**截图**一并发送——大选区会自动切成多块，每块保留原分辨率，避免被服务端重采样后糊掉。

**上下文。** 除了选段，还会带上相邻段落、**你自己在文献里做的高亮与批注**、以及 Supporting Information（正文放不下的推导、参数表通常在那里）。

**公式排版。** 回答里的 `$...$` / `$$...$$` 由打包的 [KaTeX](https://katex.org/) 渲染。长公式可以横向滚动。

## 功能

| | |
| --- | --- |
| 划词提问 | 划选文字 → 弹出「解释这段 / 翻译 / 有何作用」，答案流式出现在侧边栏 |
| 继续追问 | 侧边栏里可以就同一篇文献连续追问 |
| 公式截图 | 把划选区域裁成图片随提问发送，供模型识别文字层还原不出的公式 |
| 上下文 | 相邻段落、你的标注与笔记、Supporting Information、长文档检索 |
| 公式渲染 | 完整 KaTeX，含分式、根号、矩阵、范数、大定界符、黑板体 |
| 会话存档 | 主存为 Zotero 子笔记，另有 JSON 镜像 |
| 调用日志 | 只记元数据（tokens、耗时、错误），不记正文 |
| 深度思考 | 支持 `deepseek-flash` 的思考模式，推理过程可折叠查看 |
| 多个服务商 | 10 个预设（DeepSeek、OpenAI、Anthropic、通义、智谱、Moonshot、硅基流动、OpenRouter、Ollama、自定义） |

## 安装

1. 从 [Releases](../../releases) 下载最新的 `.xpi`
2. Zotero → 工具 → 插件 → 齿轮 → Install Plugin From File…
3. **完全退出 Zotero 再重新启动**

> 第 3 步不是客套话。Zotero 在启动时把插件脚本读进内存，安装后不重启**不会加载新代码**——表现为「装了但没变化」。这一条在开发过程中坑过很多次。

**要求**：Zotero 7 或更高（开发环境为 Zotero 10）。公式截图需要 `deepseek-flash` 或其他支持视觉的模型；`deepseek-v4-pro` 不接受图片。

## 使用

### 划词提问

在 PDF 里划选一段文字，弹出的小菜单里选：

- **解释这段** —— 讲解选中内容的含义
- **翻译** —— 译成中文，公式保持 LaTeX
- **有何作用** —— 说明这段在全文中的角色

答案会出现在右侧边栏（`Highlight Ask` 面板）。如果边栏没打开，会退回到浮动面板。

### 面板按钮

| 按钮 | 作用 |
| --- | --- |
| **带图 ✓ / ✗** | 提问时是否附带划选区域的截图。问公式时打开 |
| **全文** | 是否发送整篇文档。长文档会自动让位给检索，见下 |
| **截图预览** | 把划选区域裁成 PNG 存到数据目录，用于核对截图范围是否正确 |
| **复制** | 复制最近的回答 |
| **清空** | 开始新会话（已存档的不受影响） |

状态行会显示**本次将发送的内容与 token 估算**——包括截图张数与全文/检索模式。成本可见是有意的：整篇发送与检索相差约 11 倍。

### 上下文开关（设置里）

- **相邻段落** —— 选中片段附近的原文
- **我的标注与笔记** —— 你在本文里的高亮、批注、笔记。**免费且信息量大**：它们记录了*你认为*哪里重要
- **Supporting Information** —— 随正文附带的补充材料
- **长文档检索** —— 见下一节

---

## 长文档：检索而不是截断

一本书约 40 万 tokens，塞不进任何上下文窗口。

**原先的做法是保留开头 60% + 结尾 40%，中间丢掉。** 于是「在读第 8 章时问第 1 章的内容」不可能答对——**不是模型能力问题，是输入里根本没有**。

现在改为**本地检索**（BM25，零 API 成本，不需要嵌入服务）：

| 策略 | tokens/次 | 成本/次 |
| --- | --- | --- |
| 全文（12 万字符预算） | 35,343 | $0.0053 |
| **检索 5 段** | **3,122** | **$0.0005** |

决策规则：**放得下就整篇发送，放不下就只检索**。截断发送是最差的组合——付了全额成本，却丢掉中间。

在 541 页的教材上实测的检索判别力：

| 查询 | 命中位置 |
| --- | --- |
| 监督学习 | 2% |
| 反向传播 | 18–20% |
| 正则化 | 24–27% |
| 概率论 | 79–80% |

### ⚠️ 检索的局限（重要）

**检索词是「划选的原文」，不是你的问题。** 因为提问通常是中文，而文献是英文——中文问题检索不到英文正文。

这带来一个直接后果：**问「什么是监督学习」而正文写的是 `supervised learning` 时，只有在问题里出现英文术语才检索得到。**

这是**词面匹配，不是语义检索**。它擅长找到与选段同主题的段落，不擅长跨语言或同义改写。真要做语义检索需要引入嵌入模型，目前没有做。

如果检索效果不好，可以：

1. 在问题里带上英文术语（成本最低）
2. 把「检索段落数」调大（8–10 段也才 4–5 千 tokens，仍远低于全文）
3. 关掉「始终优先检索」，退回全文模式（贵约 11 倍，但覆盖全书）

## 配置

设置位置：Zotero → 编辑 → 设置 → Highlight Ask。

### 服务商

10 个预设，选中后自动填入 `baseUrl` 与推荐模型。用中转或自建服务时选「自定义」。

**API Key 由 Zotero 的 prefs 系统保存**（`extensions.zotero.highlightask.apiKey`），与其他 Zotero 设置一样是明文存在配置文件里。这是 Zotero 插件的常规做法，但请知悉。

### 模型选择

- **`deepseek-flash`** —— 默认。唯一的**多模态**模型（公式截图需要它），价格也最低
- **`deepseek-v4-pro`** —— 更强，但不接受图片，价格约为 flash 的 4 倍

> `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 停止服务。

### 高级

- **请求参数（JSON）** —— 透传给 API 的额外字段，例如 `{"reasoning_effort":"high"}`
- **温度** —— 留空用服务商默认
- **思考模式** —— `deepseek-flash` 默认开启，`reasoning_content` 会以可折叠区块显示

## 已知限制

- **只在 Zotero 10 / Linux 上验证过。** 未在其他版本或平台测试
- **检索是词面匹配**，不是语义检索（见上）
- **`.doc` / `.docx` 格式的 SI 读不到** —— Zotero 不索引 Word 文档（其 `isCachedMIMEType` 只覆盖 PDF、HTML、EPUB）。`.docx` 理论上可以自己解 zip，`.doc` 是 OLE 二进制，纯 JS 基本做不了
- **SI 判定是启发式的** —— 优先读文档首页的自述（"Supporting Information for..."），读不到文本时才回退到文件名特征。权衡是**精度优先**：漏掉一份 SI 只是少发材料，把正文误判成 SI 会误导模型
- **公式截图依赖阅读器的内部结构。** 它从 PDF 画布裁剪；若 Zotero 改动了阅读器的 DOM 结构，截图会失效（表现为「截不到」或裁错位置）
- **没有多模态模型时无法识别复杂公式** —— 只有文本层可用

## 开发

```sh
npm install
npm run build      # 打包 + 类型检查 + 6 项校验
npm run test:local # 261 项单元测试
```

`npm run build` 会依次执行：

| 检查 | 拦截什么 |
| --- | --- |
| `tsc --noEmit` | 类型错误 |
| `check-sandbox-globals.py` | 使用了插件沙箱不提供的全局；以及**不存在但语法合法**的 Zotero API（如 `getText()`） |
| `check-manifest.py` | `update_url` 非法、图标尺寸不符等会导致 Zotero 拒绝安装的问题 |
| `check-pane.py` | 设置页的 XML 能否被 Zotero 的包装方式解析 |
| `check-package.py` | 直接检查产出的 XPI 是否含必需文件 |
| `check-template-literals.py` | 模板字符串里出现反引号导致提前终止 |

每一项都对应一个真实踩过的坑，注释里写了原委。

### 渲染回归检查

```sh
scripts/render-check/run.sh
```

在**真实 Gecko**（无头 Firefox）里渲染公式，并与 KaTeX 原生输出并排对比。

这个工具是必需的，因为有三类问题**读代码和单元测试都发现不了**，只有渲染出来才暴露：

| 问题 | 症状 |
| --- | --- |
| SVG 元素建在 HTML 命名空间 | 范数竖线消失，公式其余部分正常 |
| `viewBox` 被小写化成 `viewbox` | SVG 失去坐标系，路径完全不画 |
| 字体未加载 | 上下标挤在一起、字形扁平 |

前两类都真实发生过，而且都被误判为「样式问题」排查了多轮。

## 代码结构

```
src/
  modules/
    chatView.ts     侧边栏界面：流式显示、追问、状态行、上下文开关
    readerPopup.ts  划词弹窗按钮；选段清洗与几何缓存
    deepseek.ts     流式客户端（SSE、思考模式、可中止、重试降级）
    prompts.ts      分层提示词；选段/全文/标注/SI/检索的组装
    context.ts      上下文来源的统一组装
    retrieval.ts    本地 BM25 检索（切块、分词、排序、定位）
    screenshot.ts   选区截图：坐标换算、分块、自绘滚动条
    markdown.ts     Markdown → DOM（零 innerHTML）
    katex.ts        KaTeX 渲染；HTML→节点树；字体路径处理
    fulltext.ts     全文提取（attachmentText，未索引时按需提取）
    notes.ts        会话存档：子笔记 + JSON 镜像
    storage.ts      数据目录读写
    requestLog.ts   仅元数据的调用日志
    providers.ts    服务商预设与设置校验
  data/providers.data.ts   预设表（设置页与主程序共用）
addon/
  bootstrap.js      插件入口
  manifest.json
  prefs.js          默认设置
  content/          设置页（XHTML + JS）
  assets/fonts/     KaTeX 字体（20 个 woff2）
```

### 三个关键实现决定

**1. 划词弹窗必须「先插入、后绑定」。** `append()` 内部用 `cloneInto` 把 DOM 克隆进阅读器的上下文，**事件监听器不会保留**。所以必须先把按钮插进去，再在克隆后的节点上重新绑定。插入本身也必须同步完成。

**2. Markdown 渲染全程不碰 `innerHTML`。** 模型输出的内容经过 `markdown.ts` 与 `katex.ts` 转成节点树，再由 DOM API 建元素。KaTeX 的 `renderToString` 返回字符串，因此有一个小的 HTML 解析器把它转成节点树——它必须**保留属性名大小写**（SVG 是大小写敏感的）、**用 `createElementNS` 创建 SVG 元素**。

**3. 截图必须在选区还活着的时候解析。** 点击侧栏会让 PDF 失去焦点、选区被清除，所以「按下按钮时再取选区」必然失败。几何在 `renderTextSelectionPopup` 触发时（选区仍存在）就解析并缓存，按钮只负责渲染。

### 沙箱限制

插件运行在 `Cu.Sandbox` 里，**不提供** `AbortController`、`requestAnimationFrame`、`ResizeObserver` 等。`check-sandbox-globals.py` 会在构建时拦截这些。
