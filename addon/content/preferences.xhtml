Highlight Ask

在 PDF 里划选文字 → 点「解释这段」→ 直接问 AI。
API Key 只保存在本机 Zotero 配置中，请求由你的电脑直连所填的服务商。

模型服务
选择后会填入该服务商的默认地址与模型，下面每一项都可以手动改。
兼容 OpenAI 格式的地址均可。填到域名或 /v1 即可，会自动补 /chat/completions。
回答行为
思考型模型会先输出一段推理再给结论，看不懂公式时这段往往比结论更有用。
0~2，越低越稳定。留空则不发送该参数（思考型模型会忽略它）。
上下文与存储
公式依赖的定义常常就在上一段。开销很小，建议开着。
你自己的高亮、批注和笔记。完全免费（本来就在库里），而且信息量很大—— 它们记录了你认为哪里重要。
随正文附带的补充材料（PDF / Word / HTML 均可）。 正文放不下的推导、参数表、补充图通常都在这里，问公式时很关键。
判定方式：优先看文件首页是否自述为 Supporting Information （出版商都会印，且不受文件格式影响）；仅当读不到文本时，才回退到 _si_、-suppmat 这类文件名特征。
全文取自 Zotero 已建立的索引，不必重新解析 PDF。费用明显更高， 建议默认关闭、按需在面板里临时打开。
超过则保留开头和结尾、截掉中间（论文的摘要与结论通常最有用）。
随文献同步、可全文检索、可直接编辑。这是主要存档。
结构化的副本，便于以后做历史面板或导出。
提示词
分三层：角色 → 阅读场景 → 任务。留空表示使用内置默认值。
调用日志
只记时间、模型、token 数、耗时、是否出错。不记录论文内容和 AI 回答。
（尚无记录）
公式截图
PDF 的文字层会把分式压平、上下标错位、范数竖线丢失，截图是公式唯一可靠的来源。
大段选区也能用：超过约 1300×1300 像素会自动切成多块分别发送， 每块都保留原分辨率，而不是被整体缩小。每块最多 1024 tokens，成本显示在状态行。
仅适用于 deepseek-flash（多模态）；deepseek-v4-pro 不接受图片。
调试
点一下会把当前选中区域从 PDF 画布裁成 PNG，存到数据目录的 highlight-ask/debug/ 下，并在调试输出里打印几何信息。 用来核对截图区域是否正确——裁剪位置算错时，看起来会像是模型的问题。
高级：请求参数（JSON）
直接合并进请求体，用来适配各家的思考/推理开关。留空则不附加。
DeepSeek 用 {"reasoning_effort":"high"}（可选 low / high / max）。
若服务商报「不支持的参数」，插件会自动去掉这些字段重试一次。
